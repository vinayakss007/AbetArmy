# AI Configuration Guide

Craq uses a multi-provider AI gateway that supports multiple LLM providers simultaneously with automatic fallback. This architecture ensures high availability and allows cost optimization by routing different tasks to different providers.

## Architecture Overview

```
Request -> AI Service
              |
              v
    +-------------------+
    | Provider Fallback  |
    | Chain              |
    |                   |
    | 1. OpenAI         |---> Success? Return response
    | 2. Anthropic      |---> Success? Return response
    | 3. Groq           |---> Success? Return response
    | 4. Ollama         |---> Success? Return response
    | 5. Custom         |---> Success? Return response
    |                   |
    | All failed?       |---> 503 Service Unavailable
    +-------------------+
```

The AI service (`src/services/ai.service.ts`) uses the configuration from `src/config/ai.config.ts` to:

1. Discover available providers from environment variables
2. Try each provider in fallback order
3. Retry failed requests up to `AI_MAX_RETRIES` times per provider
4. Return the first successful response with the provider name

## Provider Setup

### OpenAI

1. Get an API key from [OpenAI Platform](https://platform.openai.com/api-keys)
2. Add to `.env`:

```bash
OPENAI_API_KEY=sk-proj-...
OPENAI_MODEL=gpt-4o-mini          # Optional (default: gpt-4o-mini)
OPENAI_BASE_URL=https://api.openai.com/v1  # Optional
```

**Available models:** gpt-4o, gpt-4o-mini, gpt-4-turbo, gpt-3.5-turbo

### Anthropic

1. Get an API key from [Anthropic Console](https://console.anthropic.com/settings/keys)
2. Add to `.env`:

```bash
ANTHROPIC_API_KEY=sk-ant-api03-...
ANTHROPIC_MODEL=claude-3-haiku-20240307  # Optional (default)
ANTHROPIC_BASE_URL=https://api.anthropic.com  # Optional
```

**Available models:** claude-3-opus-20240229, claude-3-sonnet-20240229, claude-3-haiku-20240307

### Groq

1. Get an API key from [Groq Console](https://console.groq.com/keys)
2. Add to `.env`:

```bash
GROQ_API_KEY=gsk_...
GROQ_MODEL=llama-3.1-70b-versatile  # Optional (default)
GROQ_BASE_URL=https://api.groq.com/openai/v1  # Optional
```

**Available models:** llama-3.1-70b-versatile, llama-3.1-8b-instant, mixtral-8x7b-32768

Groq provides extremely fast inference (tokens/sec) at lower cost.

### Ollama (Local Models)

1. Install Ollama from [ollama.ai](https://ollama.ai)
2. Pull a model:

```bash
ollama pull llama3
ollama pull mistral
ollama pull codellama
```

3. Add to `.env`:

```bash
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=llama3  # Optional (default: llama3)
```

**Note:** When running in Docker, use `http://host.docker.internal:11434` as the base URL to reach the host machine's Ollama instance.

### Custom OpenAI-Compatible Provider

For any provider that implements the OpenAI API format (e.g., Together AI, Fireworks, local vLLM):

```bash
AI_COMPATIBLE_API_KEY=your-api-key
AI_COMPATIBLE_BASE_URL=https://api.together.xyz/v1
AI_COMPATIBLE_MODEL=meta-llama/Llama-3-70b-chat-hf
AI_COMPATIBLE_NAME=together  # Identifier for logging
```

## Fallback Order Configuration

The default fallback order is: openai > anthropic > groq > ollama > custom

Override with the `AI_FALLBACK_ORDER` environment variable:

```bash
# Prioritize local Ollama, fall back to cloud providers
AI_FALLBACK_ORDER=ollama,groq,openai,anthropic

# Use only Anthropic and OpenAI
AI_FALLBACK_ORDER=anthropic,openai
```

Only providers with valid credentials will be used regardless of the fallback order.

## Rate Limiting and Token Budgets

```bash
# Maximum retries per provider before moving to next (default: 2)
AI_MAX_RETRIES=2

# Request timeout in milliseconds (default: 30000 = 30s)
AI_TIMEOUT=30000
```

Each provider handles its own rate limiting. If a provider returns a 429 (rate limited), the gateway moves to the next provider in the fallback chain.

## Streaming Support

The `/api/ai/chat` endpoint supports streaming when `stream: true` is passed:

```json
{
  "messages": [{"role": "user", "content": "Hello"}],
  "stream": true
}
```

Streaming uses Server-Sent Events (SSE). The response is chunked and delivered as it is generated by the provider. Not all providers may support streaming equally well.

## How to Add a Custom Provider

To add a new provider type to the gateway:

1. **Update `src/config/ai.config.ts`:**

Add detection logic in `getProviders()`:

```typescript
if (process.env.MY_PROVIDER_API_KEY) {
  providers.push({
    name: 'my-provider',
    type: 'openai-compatible', // or create a new type
    apiKey: process.env.MY_PROVIDER_API_KEY,
    baseUrl: process.env.MY_PROVIDER_BASE_URL || 'https://api.my-provider.com/v1',
    model: process.env.MY_PROVIDER_MODEL || 'default-model',
    enabled: true,
  });
}
```

2. **Update `src/services/ai.service.ts`:**

If the provider uses the OpenAI API format, the `openai-compatible` type handles it automatically. For providers with unique APIs, add a new case in the provider dispatch logic.

3. **Add to fallback order:**

```bash
AI_FALLBACK_ORDER=my-provider,openai,anthropic
```

## Cost Optimization

Different AI tasks have different complexity requirements. Optimize costs by:

### Use Cheaper Models for Simple Tasks

- **Categorization** (POST /api/ai/categorize): Simple classification task. Use gpt-4o-mini, claude-3-haiku, or llama-3.1-8b-instant.
- **Similar Issues** (POST /api/ai/similar-issues): Semantic matching. Mid-tier models work well.
- **Solution Drafts** (POST /api/ai/solution-draft): Benefits from larger models for quality.
- **Summarization** (POST /api/ai/summarize): Mid-tier models handle well.
- **Chat** (POST /api/ai/chat): Use the most capable model for best user experience.

### Strategy: Local + Cloud Hybrid

1. Set Ollama as primary for development and low-traffic periods
2. Use Groq for fast, cost-effective inference on simple tasks
3. Reserve OpenAI/Anthropic for complex chat interactions

```bash
AI_FALLBACK_ORDER=ollama,groq,openai,anthropic
```

### Monitor Usage

Track which provider handles each request by checking the `provider` field in API responses. Use this data to understand cost distribution and optimize the fallback order.

## Local Development with Ollama

For development without API costs:

1. Install Ollama:
   ```bash
   # macOS
   brew install ollama

   # Linux
   curl -fsSL https://ollama.ai/install.sh | sh
   ```

2. Start Ollama:
   ```bash
   ollama serve
   ```

3. Pull a model:
   ```bash
   ollama pull llama3
   ```

4. Set in `.env`:
   ```bash
   OLLAMA_BASE_URL=http://localhost:11434
   OLLAMA_MODEL=llama3
   ```

5. Remove cloud provider keys from `.env` to ensure only Ollama is used.

Ollama runs entirely locally with no API costs or rate limits. Model quality varies; llama3 (8B) is fast, while llama3:70b provides better quality but requires more RAM (40GB+).

## Troubleshooting

| Issue | Solution |
|-------|----------|
| All AI endpoints return 503 | No providers configured. Set at least one API key. |
| Timeout errors | Increase `AI_TIMEOUT` or switch to a faster provider (Groq). |
| Ollama not connecting in Docker | Use `http://host.docker.internal:11434` instead of localhost. |
| Rate limited (429) | The gateway auto-falls back. Add more providers or reduce request frequency. |
| Poor response quality | Switch to a more capable model (gpt-4o, claude-3-opus). |
